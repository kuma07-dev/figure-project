## 台日一番賞 C2C 跨境價格監測、預警與成本精算系統

### 以日本樂天市場為首階段資料來源的 10 天 MVP 專題

### 1. 核心商業發現：台日雙邊市場的特殊價格逆轉機制

台日一番賞市場在「官方抽獎的一手價格」與「玩家個人轉售的二手價格」之間，存在明顯且有趣的價格聯動現象。

- **日本市場：低原價，但熱門角色二手溢價高**
    
    日本一番賞單抽價格通常約 700–800 日圓，但熱門作品、人氣角色、特殊造型或最後賞，可能因玩家基數大、收藏需求強與社群討論熱度，在樂天市場、Mercari、駿河屋等二手／零售平台出現遠高於原價的價格。
    
- **台灣市場：一手價格高、非熱門角色二手價格下跌快**
    
    台灣一番賞單抽價格通常約 260–350 元。當台灣代理版上市後，市場供給增加，非熱門角色、小賞與雜項常因玩家急於回血而快速降價。
    
- **台日間可能存在短暫的時間差機會**
    
    當日本市場中的特定角色價格先上漲，而台灣市場尚未充分反映時，台灣二手價格可能在後續受到日本市場熱度帶動。反過來說，若台灣代理版上市造成局部商品價格偏低，也可能形成跨境價格差的觀察機會。
    

本系統的目的不是保證套利，而是透過持續價格資料、落地成本計算與規則化預警，找出值得進一步觀察的商品與價格異常。

---

### 2. 系統核心目標：建立「日拍價格領先指標」的雛形

系統不只比較某一天台日兩地的靜態價差，而是記錄日本市場價格的變化，建立價格趨勢資料。

第一階段以**日本樂天市場**為唯一自動資料來源，針對指定的一番賞作品、角色與獎項定期抓取商品資訊。後續若有時間，再擴充 Mercari、駿河屋，以及台灣蝦皮或手動匯入的台灣價格資料。

系統將完成以下功能：

- 定期抓取樂天市場中指定關鍵字的一番賞商品。
- 保存每次抓取的價格快照，建立歷史價格資料。
- 用中位數而非單純平均數，降低極端高價商品造成的誤差。
- 觀察近 48 小時或近幾次抓取的價格變動。
- 當價格上漲幅度達到設定門檻時，顯示「潛在漲幅預警」。
- 輸入匯率、運費與平台費用後，計算從日本購入並運回台灣的預估落地成本與損益兩平價格。
- 以角色人氣、賞別稀有度、造型、品質與價格動能進行簡化推薦評分。

---

### 3. MVP 資料範圍與限制

為了在 10 天內完成可展示的網站，系統範圍會先縮小：

- 僅監測日本樂天市場。
- 選擇 3 個一番賞作品。
- 每個作品設定 3–5 個主要角色或獎項。
- 每個角色以日文關鍵字搜尋，例如：`一番くじ 呪術廻戦 五条悟`
- 每日固定時間爬取一次，或展示時手動執行爬蟲。
- 台灣價格先設計為「使用者手動輸入」，或暫時只做成本試算，不自動爬取台灣平台。

系統也會清楚說明資料限制：

- 樂天市場取得的是商品刊登價，不一定等同實際成交價。
- 價格僅提供市場觀察與專題分析，不代表保證獲利。
- 爬蟲會採低頻率、加入延遲，並遵守網站公開資料與使用規範。

### 4. 系統功能設計

#### （1）樂天市場價格爬蟲

Python 爬蟲依照設定關鍵字擷取：

- 商品名稱
- 商品價格（日圓）
- 日本國內運費
- 商品網址
- 商品圖片網址
- 搜尋關鍵字
- 抓取時間

系統會建立基本清洗規則，排除可能影響比較的商品，例如：

- 整套、套組、福袋
- 預購商品
- 非目標角色商品
- 明顯異常的超低價或超高價資料
- 重複的商品網址與資料快照

#### （2）歷史價格資料庫

使用 MySQL 與 PyMySQL 儲存資料，核心是保留每次爬蟲的價格快照，而不是只存最新價格。

主要資料表包含：

- `products`：作品、角色、賞別與人工特徵分數。
- `price_snapshots`：每次抓取的價格、運費、來源、網址與時間。
- `alerts`：符合價格預警規則時產生的紀錄。

#### （3）價格趨勢與預警

網站會顯示：

- 最新價格
- 歷史最低價格
- 歷史中位數價格
- 最近一次價格變動百分比
- 歷史價格折線圖
- 資料樣本數

初版預警規則可設定為：

> 若某商品最近兩次或 48 小時內的中位數價格上漲 15% 以上，且有效樣本數至少 5 筆，則標示為「潛在漲幅預警」。
> 

這個規則是「市場觀察訊號」，而不是投資或獲利承諾。

#### （4）跨境落地成本與利潤試算

使用者可以輸入：

- 商品價格（日圓）
- 日本國內運費（日圓）
- 日圓匯率
- 代購費率
- 國際運費／材積費
- 台灣平台手續費率
- 預估台灣售價

系統計算：

```
商品台幣成本 = （商品日圓價格 + 日本運費）× 日圓匯率

預估落地成本 = 商品台幣成本 ×（1 + 代購費率）+ 國際運費

預估淨利 = 台灣預估售價 − 預估落地成本 − 台灣預估售價 × 平台手續費率
```

並顯示：

- 預估落地成本
- 損益兩平售價
- 預估淨利／淨利率
- 建議標示：`可觀察`、`需謹慎`、`不建議`

#### （5）五大特徵加權矩陣

第一版不使用機器學習，而是採人工設定、可調整權重的評分方式，避免資料量不足造成錯誤判斷。

評分面向包括：

- **作品與角色人氣**：Rank S 至 Rank C 或 0–5 分。
- **賞別與稀有度**：A 賞、B 賞、最後賞、特殊配件等。
- **公仔姿勢與造型吸引力**：特效件、特殊姿勢、限定造型。
- **做工品質與社群評價**：可手動記錄「邪神」、「崩壞」、「塗裝不穩」等負面備註。
- **價格動能**：近期價格漲幅與預警狀態。

初版推薦分數：

```
推薦分數 =
人氣 × 30%
+ 稀有度 × 25%
+ 造型與特效 × 20%
+ 品質評價 × 15%
+ 價格動能 × 10%
```

### 5. 系統架構與技術應用

```
樂天市場公開商品頁
        ↓
Python 爬蟲（requests、BeautifulSoup）
        ↓
資料清洗、關鍵字比對、異常值排除
        ↓
MySQL 資料庫（PyMySQL）
        ↓
Flask 網站後端
        ↓
HTML / CSS / JavaScript 網頁
        ↓
價格走勢圖、預警、成本試算與推薦分數
```

專題將應用目前所學：

- **HTML / CSS**：商品清單、詳情頁、試算表介面。
- **JavaScript**：前端互動、表單計算、Chart.js 價格走勢圖。
- **Python**：爬蟲、資料清洗、預警邏輯、成本計算。
- **MySQL**：商品與歷史價格快照儲存。
- **PyMySQL**：Python 與 MySQL 的連接。
- **Git**：專題版本管理與成果紀錄。
- **網路爬蟲**：樂天市場公開商品資料蒐集。

Linux 不列入本次 MVP 必要範圍，未來可作為部署與伺服器排程的延伸。

---

### 6. 預期成果

完成後，使用者可以：

1. 在網站查看指定一番賞角色的樂天市場商品與目前價格。
2. 點入商品或角色，查看歷史價格走勢。
3. 發現近期達到設定漲幅的潛在價格預警。
4. 輸入匯率、運費與平台費率，試算從日本購入後的台灣落地成本。
5. 透過五大特徵評分，作為商品研究與優先追蹤的參考。
6. 未來擴充台灣資料來源後，驗證「日本市場價格先行、台灣市場延遲反應」的商業假說。

這樣的專題保有台日跨境一番賞市場分析的特色，完成一個具備爬蟲、資料庫、網站、視覺化與成本試算功能的可展示 MVP。
