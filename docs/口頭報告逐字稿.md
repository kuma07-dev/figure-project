## Slide 1｜台日一番賞價格監測系統

**畫面重點文字：**
- 10 天 MVP 專題
- 日本樂天市場價格爬蟲
- 歷史價格趨勢與預警
- 跨境落地成本試算

**逐字稿：**

教授好，各位同學大家好。我們這組今天要報告的期中專題，叫做「台日一番賞價格監測系統」。我們用十天的時間，從零做了一個可以抓日本樂天市場價格、記錄歷史趨勢、甚至幫你算從日本買回台灣划不划算的小網站。等一下大概十五分鐘，我會把我們到底做了什麼、過程踩過哪些坑、最後學到什麼，一次講給大家聽。先講結論，這十天我們真的做出一台會自己跑、會存資料、會畫圖表的機器，雖然很小，但它是活的。

## Slide 2｜為什麼會選這個題目

**畫面重點文字：**
- 日本單抽約 700–800 日圓
- 台灣單抽約 260–350 元
- 兩地價格差很多，值得量化看看

**逐字稿：**

先講講我們為什麼選這個題目。大家應該都知道，一番賞就是用抽的買公仔的那種抽獎。日本那邊單抽大概七百到八百日圓，換算台幣一百五到一百七左右；可是台灣單抽要兩百六到三百五十塊，價差其實不小。我們就在想，兩邊價格差這麼多，是不是有機會可以觀察出什麼。再加上我們發現，日本市場熱門角色在二手市場可以溢價好幾倍，台灣反而是代理版一上市、非熱門角色立刻跌價。這個落差讓我們很想知道，能不能用程式把這件事量化，也順便練習我們學過的爬蟲跟資料庫。

---

## Slide 3｜我們小組的市場觀察

**畫面重點文字：**
- 日本：一手便宜、熱門角色二手溢價高
- 台灣：一手偏貴、非熱門角色二手跌得快
- 台日之間可能有一段時間差

**逐字稿：**

我們把觀察整理成三句話。第一，日本市場一手價格便宜，但熱門角色的二手溢價很高，因為玩家基數大、收藏需求又強。第二，台灣市場一手偏貴，非熱門角色二手跌得很快，因為代理版一上市、供給就爆量，玩家急著回血。第三，兩邊中間可能有一段時間差，日本先漲、台灣還沒反應，或者是反過來。所以我們想做一個「價格領先指標」的雛形，一直記錄日本價格的變化。不過要先講清楚，我們做的不是保證套利，比較像是一個市場觀察的工具，這是我們從頭到尾一直提醒自己的。

## Slide 4｜十天能做多少？先把範圍縮小

**畫面重點文字：**
- 只監測日本樂天市場一個來源
- 三部作品、九個角色
- 每天固定爬一次價格
- 台灣價格先不自動爬

**逐字稿：**

題目聽起來很大，可是我們只有十天，所以決定先把範圍鎖小。第一階段只監測日本樂天市場這一個來源，選了三部作品，死神、火影忍者、航海王，每部三個角色，總共九個角色；每天固定爬一次價格；台灣的價格先不自動爬，留著以後再擴充。我們把目標訂成四件事：抓資料、存歷史、看趨勢、算成本。其實這個範圍我們開會時吵了很久，有人想一次做多一點，最後我們還是決定先鎖住，因為我們很清楚，與其做一個空殼，不如把一條路走到底。

## Slide 5｜系統怎麼跑？一張圖講完

**畫面重點文字：**
- 樂天 API → 爬蟲清洗 → MySQL → Flask → 網頁與圖表
- 技術：Python、requests、PyMySQL、Chart.js、Git

**逐字稿：**

我們整個系統的流程大概是這樣。早上固定的時間，程式去問日本樂天的 API，拿到最新的商品資料；接著爬蟲把資料清洗一遍，只留下我們要追蹤的角色商品；洗乾淨的資料存進 MySQL 資料庫；網站是用 Flask 寫的，從資料庫把資料撈出來，丟給前端 HTML 跟 JavaScript，畫成表格跟折線圖。技術上我們用了 Python、requests、PyMySQL、Flask、Chart.js，還有 Git 做版本管理，等於把這學期學到的東西串在一起用了一次。資料庫是架在本機的 MySQL，我們把 .env 的設定分開，金鑰不會進到 Git 裡面。

---

## Slide 6｜資料庫設計：把價格變成歷史

**畫面重點文字：**
- tracked_items：追蹤角色與關鍵字
- listings：樂天上的實際商品
- price_snapshots：每一次的價格快照

**逐字稿：**

資料庫這塊我們花了很多心思。核心概念是「不要只存最新的價格」，而是每一次爬取都存一張快照，這樣才看得出趨勢。我們建了三張表：tracked_items 記錄要追蹤的角色和搜尋關鍵字；listings 記錄樂天上實際的商品，用商品網址當唯一鍵，避免重複建檔；再來是 price_snapshots，每一次爬到的價格都寫進這一張表。為什麼要拆成三張？因為同一個角色，樂天上可能有很多賣家在賣，每個賣家價格都不一樣，所以我們把「角色」跟「商品」分開，才能比較同一個角色的多筆價格。建完表之後，我們還先塞假資料跑過一遍，確認外鍵跟查詢都沒問題才繼續。

## Slide 7｜最痛苦的一段：跟樂天 API 搏鬥

**畫面重點文字：**
- 2026 新版端點＋Access Key 防火牆
- 需要帶 User-Agent、Referer、Origin 表頭
- JSON 回傳有雙層外殼要拆

**逐字稿：**

接下來講整個專題我們卡最久的一段，就是樂天 API。第一版我們一直拿不到資料，查了很久才發現，樂天 2026 年換了新端點，而且除了 Access Key，還要求帶上 User-Agent、Referer、Origin 這些表頭，要模擬像是從樂天主頁發出來的請求，不然防火牆會直接把我們重導走。我們在測試檔裡印了一堆訊息，一版一版慢慢試，中間還遇到重導向偷偷把資料換成 HTML，我們加上 allow_redirects=False 才把問題抓出來。好不容易拿到第一批資料，那時候我們整組真的在螢幕前面歡呼。再來是 JSON 回傳格式，外層包了一層 Item，圖片有時是字串、有時是物件，我們用了一堆條件判斷才把它解析乾淨。

## Slide 8｜洗掉垃圾，留下能用的

**畫面重點文字：**
- 排除套組、預購、福袋、多件合售
- 價格範圍限制在 500–30000 日圓
- 用上架總件數自動評 1–5 星熱度

**逐字稿：**

資料抓下來之後不能直接存，因為裡面混著套組、預購、福袋，這些價格跟單抽不一樣，會干擾我們的分析，所以爬蟲用關鍵字把它們濾掉；價格太誇張的，超過三萬日圓或是低於五百日圓的，也一起排除。比較好玩的是我們還寫了一個自動評分，樂天會回傳這個關鍵字目前總共有幾件商品在賣，我們就用這個數字分級距，兩千五百件以上就是五顆星、八百件以上四顆星，讓系統自己幫每個角色打人氣分數。另外我們還設計了去重複的機制，同一天同一件商品只存一筆快照，避免爬蟲跑第二次就把資料灌爆。這個想法我們自己覺得滿聰明的，等於讓市場自己告訴我們誰紅。

## Slide 9｜用中位數，不要被一筆天價騙了

**畫面重點文字：**
- 用每日中位數代替平均數
- 兩次抓取間上漲 ≥15% 且樣本 ≥5 筆 → 潛在漲幅預警
- 單筆商品對比當日中位數：低估特價／溢價偏高／價格平穩

**逐字稿：**

價格要怎麼看才準？我們原本傻傻地用平均數，結果一筆賣三萬日圓的天價商品，就會把整天的平均拉得很高，後來我們改成用中位數，把極端值擋掉，數字穩定多了。我們還定義了一條預警規則：如果一個角色最近兩天、或是兩次抓取之間，中位數價格漲超過百分之十五，而且有效樣本至少有五筆，系統就會標上「潛在漲幅預警」的燈號。每一筆商品也會跟當天的中位數比，低百分之十五以上叫低估特價，高百分之十五以上叫溢價偏高。這條規則我們討論了很久，最後決定寧可保守一點，因為它只是市場觀察的訊號，不是保證賺錢。

## Slide 10｜買回台灣到底划不划算？

**畫面重點文字：**
- 商品日圓＋運費 × 匯率 → 落地成本
- 損益兩平售價、預估淨利
- 燈號建議：可觀察／損益兩平／不建議

**逐字稿：**

光看日本價格不夠，因為從日本買回來，中間還有代購費、國際運費、台灣平台的抽成。所以我們做了一個跨境成本試算器，輸入商品日圓價格、匯率、代購費率、運費、平台抽成、預估售價，它就算出三件事：落地成本是多少、損益兩平的售價要賣多少、最後純利潤是正的還是負的。結果用燈號顯示，綠燈是可觀察、黃燈是損益兩平、紅燈是不建議。我們自己做測試，拿一個六千日圓的商品下去算，發現要賣快兩千台幣才打平，才真的體會到跨境代購不是看起來那麼好賺。輸入的欄位我們也做了防呆，亂填或填負數，程式會直接擋下來。

---

## Slide 11｜沒有機器學習，就用加權評分

**畫面重點文字：**
- 人氣 30%＋稀有度 25%＋造型 20%＋品質 15%＋價格動能 10%
- 第一版不做 ML，避免資料不足造成誤判

**逐字稿：**

評分這塊我們要誠實講，因為資料量還不夠，我們不敢直接用機器學習，怕它學出錯誤的結論，所以改用人工設定權重的加權評分。五個面向，人氣占百分之三十、稀有度百分之二十五、造型跟特效百分之二十、做工品質百分之十五、價格動能百分之十。人氣分數就是剛剛講的自動評分，稀有度跟品質是我們人工去看賞別等級慢慢標的，價格動能就看近期漲幅。最後把五個數字加權算成一個綜合推薦分數，當作大家研究商品的一個起點，不是絕對的標準。這個做法比較土，但至少每一步的邏輯我們都看得懂，出問題也改得動。

## Slide 12｜網站長這樣

**畫面重點文字：**
- 首頁：商品清單＋目前價格＋抓取時間
- 角色詳情：四張分數卡片＋Chart.js 每日中位數折線圖＋預警燈號
- 前端樣式為手寫 CSS

**逐字稿：**

網站的部分，我們用 Flask 寫後端，前端樣式是自己手刻的 CSS。首頁是一張商品清單，可以看到每個角色的目前價格跟抓取時間，點角色按鈕會進到詳情頁。詳情頁上面是四張分數卡片，人氣、稀有度、做工、綜合推薦度；中間用 Chart.js 畫了一張每日中位數價格的折線圖；下面那張表，每一筆商品前面都有價格狀態的燈號。我們示範的時候都會先跑一次爬蟲，讓大家看到資料真的從日本抓進來。老實說前端我們改了很多版，光調表格跟燈號的配色，就花了不少時間，中間還一度想直接套現成模板，最後還是決定自己寫，版面至少我們看得順眼。

## Slide 13｜我們知道的限制

**畫面重點文字：**
- 樂天刊登價 ≠ 實際成交價
- 樣本僅三部作品、單一來源
- 系統是觀察工具，不保證獲利

**逐字稿：**

但是我們也要誠實講這套系統的限制。第一，樂天上面記錄的是刊登價，不是真正的成交價，賣家開一個高價掛著不賣，我們也會照樣記錄進去。第二，樣本目前只有三部作品、九個角色，而且只有樂天一個來源，還不足以證明台日之間真的有穩定的時間差。第三，也是最重要的一點，這個系統只是市場觀察的工具，絕對不保證獲利，我們在網站上面都有放這句提醒。這些限制我們都寫在 README 跟網站上，沒有藏起來。我們覺得，與其吹得很厲害，不如先把資料的界線講清楚，教授如果之後想檢查，也比較誠實。
